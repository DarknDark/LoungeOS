New Core Principle

The QR code is permanent.

It should never normally change.

The QR only identifies the table.

Example:

loungeos://table/table-5

or

tableId = table-5

No secret token should be printed on the QR.

The API decides whether the table can be entered.

Table State

A table can only be in one of these states:

AVAILABLE
ACTIVE
FINISHING
AVAILABLE

No active customer tab.

Scanning QR starts a new session.

ACTIVE

Customers are still dining.

Scanning the QR must NOT create another session.

Instead display:

This table already has an active tab.

If you are seated here, please call the waiter. They may have forgotten to close the previous tab.

Show only:

Call Waiter

Nothing else.

FINISHING

Customer has pressed Close Tab.

Customer is waiting for the waiter.

Display:

Waiting for your waiter...

The customer can still:

Cancel Close Tab
Continue ordering (returns table to ACTIVE)

No new customers may enter.
