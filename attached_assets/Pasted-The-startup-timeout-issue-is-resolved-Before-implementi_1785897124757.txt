Part 2 — Implement the permanent table QR workflow

We are replacing the old QR-token model.

New rule

A QR code is permanent.

It identifies the table only.

Example:

Table 1
Table 2
Table 3
...

The QR never changes unless management intentionally replaces it.

Do not generate disposable QR codes.

Do not require periodic QR regeneration.

Customer scan flow

Customer scans the QR.

If the table is AVAILABLE:

create a new table session
create a customer session
assign the scanner as the owner
show the customer dashboard

If the table already has an active tab:

Show:

"This table already has an active tab.

Please call the waiter if the previous table was already cleared."

Do not expose any previous customer information.

Pay Now

Pay Now

Flow:

Close Tab

Close Tab

Architecture

Keep this implementation simple.

The permanent table identity is now:

Table ID

NOT

Temporary QR token.

All temporary customer permissions must come from the active session, not from the QR itself.

The QR is only the doorway.

The session determines everything else.
